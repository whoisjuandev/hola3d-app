# Calendar and calculator improvements

The owner compared the app with three screens of another platform (calendar with hand-made events and a day panel, a cost calculator with multiplier profit, saved profiles and model upload, and a short quote dialog) and chose which functions to add. Only functions are taken from those screens: the look stays Hola3D's.
Branch: `feat/calendar-calculator-improvements`. Builds on `odd/tasks/workshop-modules.md` (all done, merged to main).

## Conventions (apply to every task)

- Read `README.md` and the modules named in the task first, and follow their patterns: domain rules and validation in `shared/`, a repository port with a D1 adapter and an in-memory adapter in `worker/<module>/`, routes that return `null` for foreign paths, one feature folder per screen in `src/features/<module>/`.
- UI copy is Spanish (Rioplatense, voseo). Code, comments, tests, commits and docs are English.
- Reuse the existing visual language and CSS tokens in `src/index.css`. No new dependency of any kind. Every screen must work on a phone.
- Money is whole pesos (integers). Weights are whole grams. Print time is stored in minutes.
- Schema changes are new files in `migrations/` (never edit an existing one). Extend `seed/dev.sql` with sample rows for what the task adds.
- Every new API route gets tests in the style of the existing route tests: status, body, and that rejected input leaves stored data unchanged. Every domain rule gets a test in `shared/`. Write each test before its code and see it fail.
- Writes that two requests can race decide inside one guarded SQL statement, never read-then-write. Partial edits write only the fields the request sent.
- Errors follow the existing shape: `{ error }` in Spanish, 422 with `fields` for invalid data.
- Update `README.md` for what the task adds or changes.
- Before finishing: `npm test && npm run typecheck && npm run lint` must pass.
- Working rules for workers: do not commit or push; no `git stash` or other git command that changes the tree or history; bound every command that could hang with a time limit; run tests only as `npx vitest run ...` or `npm test`; start the dev server only in the background, by PID, after test runs have finished, and stop it when done; make edits in small steps instead of one very large file write; do not touch the unrelated headless Chrome on port 9344; list any scratch path left outside the repository. For phone checks use device emulation or an iframe 390 px wide, because plain headless `--window-size=390` renders wider.

## Specs

- **S1 Hand-made events.** Chosen option: "Eventos a mano por tipo — Entrega, retiro, reunión, tarea y recordatorio, con hora y nota, además de lo que ya sale solo." The owner can create, edit and delete calendar events. Fields: type (`entrega`, `retiro`, `reunion`, `tarea`, `recordatorio`), title, date, optional time, optional note, and a done flag. `GET /api/calendar` returns them in its range next to the items it already returns. Month and week views show them with one colour per type and a legend; a done event is shown struck through.
- **S2 Day panel.** Chosen option: "Panel del día al costado — Tocar un día del mes y ver al lado todo lo de ese día, con botón para agregar." In the month view, choosing a day selects it (today is selected on load) and a panel next to the grid shows everything of that day in time order: hand-made events, order deliveries, project due dates, service tasks due and planned print jobs, each linking where it links today. The panel has a button to add an event on that day, lets the owner mark an event done, edit it and delete it, and has a link to open that day's week. On a phone the panel sits below the grid. Choosing a day no longer jumps to the week view; the week view stays reachable from its toggle.
- **S3 Profit by multiplier.** Chosen option: "Ganancia por multiplicador — Elegir entre multiplicador o porcentaje, con atajos como mayorista ×3, minorista ×4 y llaveros ×5, editables." A calculation chooses how profit is set: a percentage of the production cost (as today) or a multiplier, where price before commission = production cost × multiplier. The calculator shows shortcut buttons for stored multipliers plus a custom value; the shortcuts (name and multiplier) are edited in the cost settings and start as Mayorista ×3, Minorista ×4 and Llaveros ×5. A multiplier goes from 1 to 11 with up to two decimals. The cost settings also store which mode and value a new calculation starts with. The breakdown names the mode it used ("Ganancia ×4" or "Ganancia 60 %"). A saved quote freezes the mode and value with the rest of its result; quotes saved before this change keep reading as percentage.
- **S4 Saved profiles and copy summary.** Chosen option: "Perfiles guardados y copiar resumen — Guardar un cálculo como plantilla para reusar, y copiar el resultado como texto." The owner can save the calculator's current input under a name, list the saved profiles, load one into the calculator (replacing the current input after a confirmation when it has data), rename it, overwrite it and delete it. A profile whose printer or spool no longer exists still loads, with that field left to choose again and a notice. "Copiar resumen" copies a plain-text summary for a client: each piece with quantity and price, the total, and nothing about costs or margin.
- **S5 Load a 3D model.** Chosen option: "Cargar un modelo 3D — Subir STL o 3MF y estimar gramos y tiempo. Es aproximado frente al laminador." In a calculator line the owner can pick a file. The file is read in the browser and never uploaded or stored. An STL (binary or ASCII) or the mesh inside a 3MF gives the model's volume; grams are estimated from the volume, the density of the line's material and an infill percentage the owner can change (default 15 %), and print time from the estimated grams and a print rate in grams per hour the owner can change (default 25 g/h). A 3MF that a slicer already sliced (Bambu Studio or OrcaSlicer `.gcode.3mf`) carries real grams and time: those are read and used instead of the estimate. The line shows whether its numbers are "estimado" or "del laminador", and the owner can always overwrite them. A file that cannot be read shows a clear message and changes nothing.
- **S6 Quick quote.** Chosen option: "Rápida, pero queda guardada — El mismo formulario corto, y además se guarda como presupuesto con el nombre como texto, sin crear cliente." From the calculator's result, "Cotización rápida" opens a short form: recipient name (required), product or job title (required, starting from the piece names), validity with buttons "Sin plazo", "7 días", "15 días", "30 días" and "Otro" (a date), notes or delivery time, a switch to include the cost breakdown, and an optional phone for WhatsApp. It shows the total and has three actions: "Descargar PDF" (the existing print view), "WhatsApp" and "Copiar". Any of the three first saves the quote, once, as status `enviado`, with the recipient's name and phone as text and no client record; the price is frozen as for any quote. Such a quote appears in Presupuestos with its recipient name. The print view shows the cost breakdown only when the switch was on. A quote without validity never shows as expired. Accepting a quick quote asks for the client first (the picker starts with the recipient's name, and a new client gets the recipient's phone), links the quote to that client and then creates the orders as today. A refused accept leaves no client behind. A retried save of the same quick quote form never stores a second quote. The recipient fields belong to quotes without a client: a quote that has a client does not take them.

Not chosen, so not built: photos per day, voice notes per day, resin and laser calculators.
